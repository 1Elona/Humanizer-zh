31. **Business change with an actual pending choice.** Accepted purpose: remove
    orders that can no longer be paid from the pending-payment queue. The fixture's

    `WHERE t_order.status = 'PENDING'`; previously these expired orders remained
    `PENDING` indefinitely and therefore stayed on that page. The new job sets
    `t_order.status = 'CLOSED'` only where both `t_order.status = 'PENDING'` and
    `t_order.created_at < cutoff`, with `cutoff` fixed to 30 days before the run.
    Rows exactly at the cutoff and other statuses remain unchanged. Local fixture
    DB readback confirms those results. Production has not run the job.
    The stock contract states that `t_stock.locked_qty` is stock reserved for orders
    and unavailable for new orders: available stock is `on_hand_qty - locked_qty`.
    This job does not change it. Whether closure should release the expired order's
    reservation is explicitly a pending business-owner choice; implementation of
    release is not authorized. A local technical inspection established an existing
    idempotent per-order release operation; integration is feasible, but this job
